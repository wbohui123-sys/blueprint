# @blueprint/node

本包是插件及原生 compaction 后端，消费 dsh、roster、prompt、brain、context 的纯前缀／消息读取函数和只读工具目录服务。提供节点动作、会话、纸条投递、项目隔离、素材与媒体、Git 空间及文档重建。接口与存储见 [协议.md](../../../协议.md#二包与接缝)，设计见 [图景.md](../../../图景.md)。

长工具结果在低压力下保留原文前缀。自动回收按持久请求头对应模型的真实容量和原生 tokenMeter 读数触发：默认达到窗口的 75% 时集中归档已消费的长结果，压力回落至 65% 后才允许下一批；模型容量未知时不猜测。`装资料` 可配置压力和迟滞比例。原生超窗恢复仍保留；完整历史、原文归档、错误状态、正在修改和回收后重读的文件保护不变。可核验的旧相对归档入口仍即时修复。核对见 `资料.test.js`。

分工表只有一层（2026-10-18；十步重置 2026-10-24）：每块都直接挂在派它的节点下；没有 parent、start、children、after、action、queued。同一轮派出的块互不等待，要等别的块先有的登记着、下一轮再派；轮是表上的数字，上级每派出一批记一轮（roster `轮次.js`）。旧名册里的 after、children_done 照旧读。恢复沿用 kickoff 与原生收据，首次开工不重复发交齐通知。

耦合的整体仍归一个责任节点，独立成果按接口拆分；请求携带已有事实及用户已确认的验收条件，责任与后续待办仍由现有任务表、纸条、parts／unchecked 承接。wait 与 job_output 在原本获得这些工具的会话中直接可见，长作业沿原生完成事件等待。

`verification` 通过原生 bash 后台执行长检查，begin 绑定声明输入、命令、工作目录、环境观察值哈希与作业身份，collect 归档终态和输出，compare 返回 matched／stale／unknown。目录指纹排除 Git 元数据与项目根机器证据目录，其他未跟踪或生成文件仍参与。仅在需要核对证据适用性时由接手整合的节点 compare，后续层级引用其结论和适用范围；已有日志或 CI 证据无需为生成收据重跑。matched 只说明声明项一致，不代表整合目标、未声明依赖、网络、设备或运行中改动后恢复的状态相同，也不自动完成验收。强制 hook、CI、实机和长时验收不变。成功只认原生 completed 且精确报告 exit code: 0；作业丢失、输入不稳定、日志不完整或损坏不能得到可匹配结论。核对见 `验证收据.test.js`。

call_tool 的目标参数由原生工具校验，错误返回目标定义；入口多包一层（外层 name 填 call_tool、里层才是实际调用）的剥掉照办；JSON 解析失败时返回语法原因、位置及附近文本。间接调用保留原生权限、取消、富媒体和交回信号。

note 的求助（kind=ask，不写 kind 也是）发出后调用原生 concludeTurn，同一批后续工具不执行；传达（kind=tell）不结束本轮、不用回。等回条时新纸条照送（派出去的还没全交回、它又闲着时，传达和成果发布压到全部交回再送，见《协议》2.12 纸条两种），带新事来的那一轮放行到底，它可以先回别人；没新事的一步被拒、退回原生 inbox，对应回条进入本会话账本后才恢复原来的活。回复纸条不结束回复方的当前轮。正式前置和显式条件守住模型 pre-step 与同批工具；普通纸条不会提前启动依赖者。finish 不自动回求助，欠着的求助在节点停下时由 `提醒欠求助` 叫醒它去回（详见《协议》2.12）。

publish 将成果名、版本、用途、现成入口和可选使用者写入名册，节点总表与 node_doc 可读；指定使用者收到稳定通知，发布者不等确认。wait 在任意阶段登记成果、正式交回、当前孩子、原生作业或新用户输入的 all／any 条件；保存当前阶段，事件满足后锁存实际事实，再以稳定原生输入送达并 flush。同一宿主、项目的突发复查合并，在途变化再补查；已成功固化的输入不反复 flush，失败重试和冷恢复仍核对原生收据。等待无模型轮询，完成／失败／缺失成果不冒充成功；用户停止优先。复查逐项进行：已交回的节点不收发布通知、不为通知去捞它的会话；某个节点读不回来先记下，其余照常送达，走完再一起报（发布者从 deliveryPending 看到）。Start All 复查并补送，已收输入不重复；全项目复查出事不拖垮本节点续工。改写职责清除旧等待，已发布事实仍可读。

新等待使用原生 Inbox 与 blocked 轮尾，不再写诊断事件。旧等待记录保留只读，v3→v4 冷迁移仍可恢复；`纸条等待持久化.test.js` 验证压缩存储后的关闭、冷读与恢复，无 Session 补丁。

Claude Code／Codex 不再给节点当工具（10-18 E1）：分工块选了它们的 run 由它们自己当，`外部run.js` 用命令行启动，名册上没有会话；开团队、启动待发、纸条、去掉分支、按停与继续、Start All、改写、重启、删项目都认得这种节点（协议 2.7）。每次启动先在该次 JSONL 写入 `blueprint: input`，保存实际传入的完整 prompt（固定说明、续做／冲突背景与请求）、交回格式和模型；后续事件原样追加，供 Chat 查看历次输入，不从当前文件重建历史。这里只记录 Blueprint 传给 CLI 的输入，不声称包含 CLI 内部系统指令或每次模型调用的完整上下文。核对见 [外部run输入.test.js](外部run输入.test.js)、[外部run.test.js](外部run.test.js)（假程序在 [外部run假程序.js](外部run假程序.js)）。原来衔接官方 external activation 的 `外部子任务.js` 和它的测试在 `回收站/外部工具中转-2026-10-18/`。

持续终端沿原生 `terminals`、`terminal-bash` 和六个 `terminal_*` 工具运行，正式节点和材料帮手各自拥有自己的 shell／REPL。所有权绑定确切 Agent；shell 的目录与变量跨调用保留，不随 Session 后续切目录改变。后台发送使用原生 jobs，单节点停止沿 cancel／SIGINT 中断当前发送并保留 shell；finish、重启和项目全停在工具已停稳后调用 `关闭节点终端(ctx, agents, reason?)`，按原生 list／kill 等待释放，只关闭指定 Agent 的终端。关闭后仍有原生 hasOwnerActivity 的未发布创建或失败清理时拒绝完成／重启，不冒充已经释放；这些事实留给原生所有者／服务清理处理。进程重启后没有终端恢复。核对见 [持续终端生命周期.test.js](持续终端生命周期.test.js)。

用户面板终端由独立原生 `terminalController` 管理。Studio 在已校验的项目／正式会话上，用 `在项目终端执行域(ctx, agent, fn, signal?)` 包住原生 create，绑定原项目、原生当前目录与实时宿主管理端口；不进入模型角色、预测或审批，也不注入模型的后台窗口启动环境。输入与子进程继承创建时的内核项目、机器文件和管理端口边界。节点的全停不关闭用户面板终端，用户通过面板显式关闭；Agent／宿主 dispose 仍执行原生所有者清理。

工具说明唯一来源是 `prompt/工具/`。预测保留粗略估计、经验粗评、校准定稿三步，但由节点判断需要完整展开、只补相关环节或直接处理。node_doc.prediction 按需记录任一环，允许独立记录经验粗评，修正一环保留其他环的认识。程序不把读技能、交接认识或定稿作为工具权限；直接工具与 call_tool 共用角色、项目隔离、正式依赖和已提交方案的用户审核检查。

用户新建的空白分身先显示「新分身／等待你描述任务」，收到首句话后显示「正在理解任务…」。模型第一次明确本次目标时用 `node_doc.brief` 一并保存 name／description，可与职责和预测同次提交；后续普通输入不自动改名。有派出者的节点（run、helm 派出的座位分身）不用 brief：名字是派它的节点定的职位，node_doc 拦下（改名会让节点前缀重摆、缓存全断）。照见里 next 带 ask_user 不送审；人工审核开启时停下等用户回话，关闭时回复“请你综合权衡，自己决策”，由节点继续判断。请求原文与 task 保留，工作文档用稳定 documentName 寻址，改名同步文档抬头而不移动文件。

用户入口将原话记入节点文档的 record，不自动追加到 request 或 originalRequest，不因日常消息改变预测和定稿版本。原生用户消息照常送到节点；后续阶段所需的实际新要求由节点结合对话写进方案。对已交回的节点说话，同一节点过选择机重新开工，干完再交回。

node_doc.inquiry 按需保存调查目的与预计认识，不授予行动资格。不坐座位的块都是 run（已经定下的做法写进 situation，没有 approach 那格）；run 不过选择机，照请求做完用 finish 交回，不能分工、开座位、结束阶段或问用户。run 每一轮开新的，不接着用：带着问题交回的，上级开一个新 run（新 key、台写同一个，台里已经有它交的东西）接着做（叶 4，十步重置 2026-10-24）。旧执行取材快照仍按原版本验证恢复。阶段报告仍结束节点选择的这一圈并进入差异判断；此后直接修正、补某一环或重新预测由节点选择。旧 how 记录保留原指纹与执行收据；新认识不再接受 how。

divide 写任务表，四格平铺：seats（只给 helm，开座位、调范围）、stage（开线的上级记 `{stages, current, why}`，不写＝一个阶段）、shared（给这一批人共看）、blocks；没有 choice、phase、review_id，也没有 plan 那一层。自己做的方案在 plan 环节用 next 交，做不到或要别的节点补信息用 note 发求助。blocks 每一块的格子是 key／id、to、name、dispatch、bench、situation、purpose、ask、collaborators、executor、remove：key 是新的一块，id 是表上已有的一块；`dispatch:false` 只登记（名字和一句 purpose，不开会话、不写请求）；派出的写台（bench，要在派出者的分支里）和四栏；remove 去掉。这一轮的目的与停点在结构段的分工表里。定稿由系统保存为 source=self 的自主定稿，复用 strategyReview。请求、请求写入者、职责、已记录的预测认识或阶段报告计数改变后旧审议失效；普通记录追加不使它失效。重开请求清除旧审议与预测。当前预测和有效待合并入口随思考开头恢复。

execute 不调用模型转译，从同一份定稿生成本节点结构、完整子节点请求和执行安排；记录不抄定稿、不记审议流水，方案审核与终稿审核各只记一句结果（选 32），工具只返回落定与启动回执。终稿先写入本节点工作文档。需要形成或调整执行方案时提交终稿，通过后执行该方案或派人。送审按项目“人工审核”开关处理：solo 默认关闭、co-create 默认打开。关闭时提问自动选第一项（多选题也只选首项），方案、终稿和工具权限审批自动通过，无选项问题、ask_user 和等待输入的对话回复“请你综合权衡，自己决策”；spark 自然结束的对话沿同一原生输入通道自动续一句。已挂起的问题和审核沿原答复口或恢复通道处理，保留用户已保存的回答与其他节点的工作等待；自动答复按请求或轮次去重，保留系统来源，不解除用户按停。打开时 co-create 保留总节点及 spark 人工确认、子节点自动通过的规则；solo 手动打开后也送审。开关保存在 `系统文档/人工审核.json`，模型及外部程序不能改写。除 run 外节点没有提问工具，`预测.js` 退回 `NO_QUESTION_CARD`（协议 2.18）；run 照 dsh 有 ask_user_question（10-28），不等人时同样回“请你综合权衡，自己决策”；run 在 dsh 计划模式里交的计划（问题编号 `plan-review`）build 下不自动通过（`回答.js` 的 `自动选择`）；spark 用 next 交的方案和 plan 走同一条审核（协议 2.16）。反馈支持修订后重新送审，同一已通过版本的重试与恢复不重复审核；这一轮用户已亲手通过过方案（预测依据相同、还没进 complete），再交的方案和接着的 divide 都记成通过（divide 来源 plan）、不再出题（选 35）；自动通过保留终稿版本及系统来源。人工决定与送审版本保存在现有 strategyReview，待回答沿原问答通道保存、恢复。通过后执行收据与派人编号一起落名册，相同改版重试复用收据，启动失败只补齐原团队；同一审议不能执行另一改版。派出了块的 divide 落定后调用原生 concludeTurn，这一轮收尾；只登记、只去掉的不结束环节。程序按任务标识生成节点并返回编号映射，同一轮派出的块一起开工、互不等待，每一块记上级第几轮派的（roster `轮次.js`）；helm 派给座位时，同一阶段里这个座位上交回过的分身接着用，阶段变了开新分身。没有工作量档（选 30），所有节点一样按需使用节点流程（2026-10-18 起没有 print）。孩子自行判断所需流程、形成方案时送审终稿。任一节点可调整自己的子树，初始设计来源与调整权分开。子会话工具范围由 do 包提供。

finish 只有正式交回全部责任一种；普通差异报告仍留在同一节点。正常收尾由本轮成功阶段报告、待送交齐汇总或关闭人工审核后的 spark 自动答复续工；报告按会话与轮次给稳定输入身份，重复事件不重复叫醒。普通工具调用或未交回本身不再开启下一轮。直接孩子全部交回，交齐汇总叫醒母节点一次（按文档重建）；旧名册里的 after 照旧在交回时放行后置。finish 交 result、handoff（做了什么、入口、哪里没把握）、unchecked，run 可带 question，座位分身和 helm 带 status、lessons，另有 files、ask_user；没有 checked、next_stage。有台的节点交回只提交台里的改动，台外写的文件不交上去、在回执里照实列出（十步重置 2026-10-24）。启动、汇总与文档使用可恢复收据；Start All 先补齐已落定改版的材料与撤销效果，再恢复原组织，无需重新提交 payload。用户入口和纸条直接送到点名的节点；名册接续链 10-15 已删。

文档重建后端直接继承原生 `CompactionEngine`，使用原生 maintenance、活动 surface 事务及 `tokenMeter.measure(session).totalTokens`。不按压力自动压缩；context overflow 在实际替换 surface 后最多重试一次。评测脚本的 context 估计不参与运行判定。

run 和它开的子会话照 dsh 默认的 compaction-basic 走：快满自动压成模型摘要、超窗压完重试一次、手动 `/compact` 也是摘要，不提醒、不给 compact、不按文档重建（10-28 用户：run 和 dsh 对话页一模一样）。以下说的是 helm、dock。读数过 `remindFromTokens: 500000` 起每涨 `remindEveryTokens: 100000`，在那一步加一行读数提醒（`shells/上下文提醒.md`）。节点自己调 `compact`（`装收起工具`，工具只记下要点）后，下一步开始时以最新节点文档重组底座，接上它写的要点，并保留最近 `retainTokens: 40000` 的原文，边界向前扩展以完整保留最近一步与工具配对；不另调模型，要点加底座不比原历史短时保留原 context。阶段报告、孩子全部交回、请求改写的叫醒，以及手动 `/compact`、overflow 恢复走文档原文重建，纸条、回条、求助的叫醒不重建；overflow 保留当前步骤。

## 项目隔离

`src/项目隔离.js` 在节点的 `tools/execute` 生命周期中绑定项目目录，覆盖所有 worker 与继承同一组装单的帮手会话。隔离覆盖文件、搜索、命令与证据入口。启动部署那份官方 Codex app-server 和 Claude Code 时，套完沙箱再接上用户在「Agent 选择」页选的模型和思考程度（只加参数，不加放行）。家目录写入只放行官方 Codex app-server：`~/.codex/tmp`、`installation_id`（数据库改到项目 `codex-state`）；Claude Code 不另放行（2026-10-17 实测不需要，放开会让它能改用户 Claude Code 的全局设置）。

- 文件服务的解析、读取、列目录、图片读取与写入检查真实路径。只允许当前项目，公共技能目录额外只读。绝对路径、`..` 与软链接不能跨项目。普通文档在各阶段均可直接读写，总图景共用项目根目录的 `总图景.md` 入口。
- 工具执行域以 `header.cwd` 识别项目，文件解析、lstat、搜索与子进程以官方 `workingDirectory.ensure()` 的有效目录解析相对路径；`工具执行目录()` 只读该次调用的目录，不另存目录账本。`working_directory` 只能进入所属项目，单次命令的 workdir 或 shell 内 cd 不改变后续工具调用的基准。上架、媒体、截图和产物声明同样采用该目录，内部归档和回执仍按项目根保存。
- 搜索与 shell 的实际子进程通过 macOS Seatbelt 限制读取：仓库中只允许当前项目与公共技能。祖先目录只允许 lstat/realpath 所需的元数据检查，不能列目录或读内容；其他项目、`.dsh` 账本及其他项目的 Git 历史不可读；本节点产物空间的普通 Git 操作在项目范围内。新项目自动受限，无需维护黑名单。
- 命令写入允许当前项目、`/dev/null`，以及宿主通过 `getconf DARWIN_USER_TEMP_DIR` 确认的当前用户系统临时目录。缓存按类别整个可写（10-27）：用户缓存目录（`getconf DARWIN_USER_CACHE_DIR`，`…/C`，系统的显卡着色器缓存在这里）、`~/Library/Caches`、`~/.cache`（没有就建）。缓存丢了能重建，本该整台电脑共用；写不进时，报错的节点会自己绕（把 HOME 改进项目），不报错的只是每次重做、谁也看不见（10-27 mini 存不下 Godot 编好的着色器，一次验收两分多钟、10 核负载 50；本机经 dsh 沙箱＋本层规则跑真 Godot：第一次 112 秒、之后 2.4 秒）。例外照旧不能写：Blueprint、dsh 自己的缓存（`com.blueprint.desktop`／`studio`、源码版用的 `com.github.Electron`、`com.deepseek.dsh`，含 `.helper` 等后缀）、开发机打包用的 `~/Library/Caches/electron`／`electron-builder`、各 App 的自动更新状态 `*.ShipIt`（不是缓存）。节点的 bash 先经 dsh 的 bash 沙箱（`seatbeltProfileArgs`：先 `(deny file-write*)` 再只放工作区、`/tmp` 和临时目录），本层规则合并在它后面，所以缓存要写成明确的 `allow`，只在本层 `deny` 里排除不够（10-27 第一版只做了排除，部署到 mini 后照样被 dsh 那层拦住）；本机测沙箱要带上 dsh 那层入口。核对：`项目隔离.test.js` 的「三处缓存」一项（两种入口都测）。文件服务与命令沙箱共用机器文件清单：名册、纸条、节点总表、素材检索目录、模型／技能配置、用量、待回答记录与归档证据、网页索引、媒体回执只由程序更新；目录内其他文件照常可写，含机器文件的目录不能整体删除或搬走。写权限不按预测阶段区分，预测中的信息收集与执行职责由预测入口和对应 prompt 表达。默认临时目录仍设置到本项目 `.blueprint-tmp`；系统临时目录用于兼容绕过 `TMPDIR` 的原生导出工具；`/var/folders` 里除它和缓存目录外、以及 `/tmp` 不开放。该临时目录由同一 macOS 用户的程序共享，不提供项目间临时文件隔离。原有命令沙箱的规则保留，并在同一配置内追加隔离规则。模型请求提升写权限也不能解除项目边界。
- 项目 HTTP、WebSocket 与项目内 Unix socket 可互通。每次工具调用从原生 `webServer.port` 读取实际宿主管理端口，只拒绝该端口的本机出站（IPv4／IPv6）；服务存在但未就绪时拒绝启动工具。项目外 Unix socket 仍拒绝，保留 macOS DNS 服务 `/private/var/run/mDNSResponder` 例外；软链接不能借项目路径连接邻居 socket。Apple Events 出站仍禁止。命令清空继承的代理变量后直连外网，素材搜索也保留这一出口，不改宿主自身的代理设置。必须依赖显式代理的网络环境仍需另配受控出口。跨应用自动化仍可能受限。系统安装目录仍可读取以运行已有软件。
- 项目命令设置 `BLUEPRINT_PROJECT_ROOT`；临时目录在当前项目 `.blueprint-tmp`。下载、安装缓存全机共用（10-27 起，此前各项目各一份、每个新项目重下）：uv、Hugging Face、一般缓存用 `~/.cache` 下的标准位置，pip 用 `~/Library/Caches/pip`，用户自己下过的包和模型直接复用；默认不在缓存位置的 npm、matplotlib、uv 装的 Python 放 `~/.cache/blueprint/`。不修改宿主环境。旧项目 `.blueprint-tmp/cache` 里的旧缓存不再用到，没有自动删。
- 宿主界面仍管理全部项目；并行工具调用通过 AsyncLocalStorage 区分项目。包装共享服务一次，不修改 dsh 源码。
- 当前进程沙箱仅支持 macOS；其他平台拒绝进程执行，不静默退回无隔离。

工具执行域只管那一次工具调用自己读写什么。在它里面开出来的 agent 循环会一路带着它（AsyncLocalStorage），所以两处宿主操作要离开：开节点与叫醒（`会话.js` 调 `离开工具执行()`）；技能注册表的 list／get／snapshot（列技能要往上找 `.git`、读用户 skill 目录，帮手会话是 dsh 开的，只能靠这一处）。不离开时，子节点和帮手会话的技能清单可能因宿主注册表读取被限制而为空。

这不是独立用户或虚拟机级别的整机隔离，不保证隔离用户事先复制到项目内的内容、其他位置的副本或任意第三方 GUI/IPC 服务。此层解决模型通过当前文件、搜索和命令入口直接读取同仓库其他项目的问题。

加载新代码需要重启 Blueprint。已经进入会话的内容不会被文件权限撤回：若旧会话曾读取其他项目，要另开干净项目，旧记录保留供用户查看。

项目工具使用独立的后台启动环境：Godot 检查与导出仍可用 `--headless`，实际画面验证隐藏 Cocoa 窗口、禁止激活并保留 GPU 渲染；Chrome／Chromium／Playwright 子进程默认无窗口；节点开正式版 Google Chrome 时换成 App 浏览器资源（安装包 `native-resources/browser/`，由 app 的 `prepare:runtime` 放入）里的无头专用版 chrome-headless-shell 并让它用显卡画（正式版每次启动都叫醒 Google 更新程序，加参数拦不住；同目录的 Chrome for Testing 会弹钥匙串密码框卡住），没有无头专用版就照旧；matplotlib 使用 Agg，`open` 返回 WebUI 预览提示。Node 启动钩子覆盖脚本内部的浏览器调用，PATH 入口覆盖 shell 和其他程序的常用命令。Bash 启动后恢复轻量原生入口，Godot 的绝对路径、变量与嵌套 Bash 调用同样受保护；普通命令不加载 AppKit，Godot 的 `--headless` 不加载窗口保护。原有 `BASH_ENV` 入口先执行，宿主环境不变。宿主和用户手动打开的应用不加载这些入口。

10-23 补的三处漏口：
- 环境里的 `BLUEPRINT_BACKGROUND_GODOT` 指向包装，真 Godot 路径只写在包装里；包装自己挂窗口保护，所以脚本经 `env`／`nohup` 等系统程序（它们会清掉 DYLD）再叫它也照样后台。
- 登录式 shell 会重跑用户的 profile，把 Homebrew 排到包装前面。`bash -l` 在 `BASH_ENV` 里把包装目录排回最前。
- zsh 改读 `ZDOTDIR`：先照常读用户自己的同名启动文件，再排回包装、恢复原生入口。外部 run（Codex `zsh -lc`、Claude Code 快照）开的 Godot、`open` 也走这条路。
  - 这几份启动文件放在系统临时目录的纯英文路径下：zsh 5.9 从环境接含中文（例如带 0x83 字节的「部」）的 `ZDOTDIR` 会弄坏，连 `.zshenv` 都找不到。

仍不覆盖的：`sh` 里用绝对路径叫 Godot、自定义启动器、限制动态库加载的 GUI 程序，不能承诺任意第三方程序都支持后台渲染。

窗口保护由本机 clang 编译，缓存位于 `.dsh/工具缓存/`，项目获得一份 `.blueprint-tmp/` 内的可读副本（zsh 启动文件除外，见上）。保护无法构建时 Bash 启动明确报错；直接 argv 的 Godot 无窗口检查／导出及后台浏览器仍可用，需要实际 Godot 渲染的调用拒绝启动，不回退到弹窗。核对：`node --test blueprint/packages/node/后台工具.test.js`。

后台启动环境只管怎么开，不管什么时候关。节点常在 bash 里用 `&` 把浏览器放到后台，命令结束后浏览器留着、页面一直跑（10-17 一天留下 20 个，约 38GB）。`后台清理.js` 只认 Chrome 主进程（无 `--type=`）、带 `--headless`、`--user-data-dir` 在本数据根某个项目 `.blueprint-tmp/` 里的；用户自己的浏览器、别的软件和别的数据根不碰。宿主有 webServer 才装，测试夹具没有网页服务就不巡查。启动只清比本服务开得早的；巡查先 SIGTERM，5 秒后重新列一遍，只强关仍在的同一批；关闭时只发 SIGTERM，没退的下次启动再清。浏览器连用超过 30 分钟会被关，节点需要时自己重开。节点开的本地网页服务等其他后台进程不在此列。浏览器关了资料目录还在，每个几十到两百多兆（10-26 量到 758 个、22.5G），同一处另扫资料夹：服务启动扫一次、之后每 30 分钟一次，只认项目 `.blueprint-tmp/` 下三层以内、有 `Local State` 文件和 `Default` 目录的目录（`.blueprint-tmp` 自己不算、链接不跟）；带 `--user-data-dir` 的进程里出现它的名字、`SingletonLock` 指向这些进程之一、或 30 分钟内写过的都留着，其余删掉。核对：`node --test blueprint/packages/node/后台清理.test.js`。

`后台清理.js` 靠路径认，节点写相对路径或把资料目录放在作品空间里就认不出（10-26 两个无头 Chrome 停在游戏页上跑了七八个小时，用 CPU 画、吃掉六个核）。根上的关法跟着人走：dsh 给每条命令一个进程组，`&` 放出去的也留在组里；命令结束后任务表上没了它，dsh 自己要等整个服务关掉才整组收。`项目隔离.js` 包 `subprocess.spawn` 时把句柄交给 `留下的进程.js` 记在该次工具调用的节点会话名下，`会话.js` 的 `停止后台()` 和 studio 的 `停止会话后台()` 停后台任务时一起调句柄的 `terminate()`（dsh 的整组关：先 SIGTERM，宽限后 SIGKILL）。只记模型工具调用开的命令，用户终端和持续终端不记（终端另有 `关闭节点终端`）；`setsid` 脱离进程组的进程 macOS 上认不回来，仍靠 `后台清理.js` 兜底。核对：`node --test blueprint/packages/node/留下的进程.test.js`（真 dsh 服务＋真无头 Chrome）。

核对：`node --test blueprint/packages/node/项目隔离.test.js blueprint/packages/node/原生工作目录.test.js blueprint/packages/node/自定义文件入口.test.js blueprint/packages/node/核对.test.js`。原生工作树与正式节点提交的接缝另见 `app/tests/native-worktree.test.mjs`：官方只创建并进入自主 checkout；正式派出快照、节点分支归属、交回 commit 与整合仍由现有节点空间入口承担。

用户在 seat 轨道删除工作或分身，由 `删除分身.js` 校验节点当前会话与座位后复用 `去掉分支`，停止整条分支及所属外部任务、终端，历史对话、工作文档、作品与座位记忆保留；不删除 dsh 会话。Studio `node.remove` 在委托前校验项目归属。

用户删除整个项目走 `删除项目.js`：核验受管项目的真实目录和 0 号会话，暂停项目、停用 Goal，收束所属会话、后台、外部执行及 Agent 终端，刷盘后进入名册写队列再次核验目录身份。移除工作区登记后调用 macOS `/usr/bin/trash -s`，不做永久删除；移动失败恢复登记、文件仍在原位。正在删除时拒绝继续执行；同请求重试复用结果。测试通过注入临时回收目录，不操作用户回收站。
